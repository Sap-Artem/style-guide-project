# Как внести вклад

Документ описывает, как предлагать изменения в стайлгайд.

## Как предложить изменение

1. Создайте ветку от `main`: `git switch -c docs/<краткое-название>`.
2. Внесите изменения и проверьте их локально (см. раздел «Локальная сборка»).
3. Сделайте коммит по правилам ниже и отправьте ветку: `git push -u origin docs/<краткое-название>`.
4. Откройте Pull Request в `main` и опишите, что и зачем изменено.
   Если меняется правило, приведите пример «неправильно/правильно».

## Оформление коммитов

Сообщения коммитов пишутся по спецификации [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/): `<тип>(<область>): <описание>`.

| Тип | Когда использовать |
| --- | --- |
| `docs` | Новые или изменённые разделы стайлгайда |
| `fix` | Исправление ошибки в тексте или разметке |
| `ci` | Изменения в GitHub Actions |
| `chore` | Настройки, зависимости, служебные файлы |

Примеры:

- `docs(accessibility): add text accessibility rules`
- `fix(spelling): correct dash usage in examples`
- `ci: add markdown linting to workflow`

Описание пишется в повелительном наклонении и без точки в конце.
Сообщения вроде `Add files via upload` или `update` не принимаются.

## Процесс ревью

1. После открытия Pull Request GitHub Actions запускает линтер и проверочную сборку.
   Пока проверки не прошли, PR не рассматривается.
2. Рецензент оставляет комментарии и, если нарушено правило стайлгайда, указывает его код.
3. Автор исправляет замечания новым коммитом в ту же ветку.
4. После одобрения рецензента PR сливается в `main`, и сайт публикуется автоматически.

## Локальная сборка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install mkdocs-material
mkdocs serve
```

Сайт откроется по адресу `http://127.0.0.1:8000`.
Проверка разметки: `npx markdownlint-cli2 "**/*.md"`.

## Как добавить новый раздел

1. Создайте файл в папке `docs/`, имя – латиницей через дефис, например `docs/new-section.md`.
2. Начните файл с заголовка первого уровня.
3. Добавьте раздел в блок `nav` файла `mkdocs.yml`.
4. Проверьте сборку и откройте Pull Request.
